# 简历工作台 · 使用说明

本文是详细使用文档。项目介绍、截图和快速开始见仓库根目录 [README.md](../README.md)。当前版本 **4.9.0**。

# 功能详解
本地运行的简历平台 + AI Agent：多份简历管理、多套可一键切换的 A4 模板、原样预览与就地编辑、AI 诊断 / 分模块改写、JD 适配一键生成定制版、投递日历 / 看板 / 统计；以及 JD 一键抓取、投递提醒、模拟面试、经历素材库、版本对比、一页纸检查、投递复盘和英文简历。
**零依赖**（不需要 `npm install`），Node 18 以上即可，Windows PowerShell / macOS / Linux 通用。正文 DOM 结构固定（`.main` / `.option` / `.section-item-container` / `.menu-title` 等类名），任意简历切换模板时内容不会丢失。

## 快速开始

```powershell
cd resume
npm start                      # 等同于 node cli.mjs serve，自动打开 http://127.0.0.1:4321/
node cli.mjs serve --port 5000 --no-open   # 换端口 / 不自动打开浏览器
```

第一次打开后：

1. 左侧「设置」→ 选一个模型预设（DeepSeek / 通义千问 / Kimi / 智谱 / 豆包 / 硅基流动 / OpenAI / OpenRouter / Ollama / 自定义），填 API Key →「测试连接」→ 保存。
   - **Key 按供应商隔离**：每个预设单独保存自己的 Key（自定义按 Base URL 区分），切换预设只显示、使用该供应商的 Key（打码显示，原文不会返回前端）；保存 / 清除只影响当前选中的那一家。旧版本保存的单个 Key 会自动归到当时选中的供应商名下。环境变量 `LLM_API_KEY` 仍作为没有单独保存 Key 时的兜底。
   - **长时间生成不会再被 4 分钟掐断**：不设总时长上限，只在模型「太久没有返回任何内容」时中断（连接 / 首包 60 秒，流式过程中 120 秒无数据），并提示「模型超过 N 秒没有返回内容，已中断」。可用环境变量 `LLM_FIRST_BYTE_TIMEOUT_MS`、`LLM_IDLE_TIMEOUT_MS` 调整。本地服务关闭了 Node 默认的 5 分钟请求超时，流式过程中每 15 秒发送保活。
2. 还没有 Key？打开设置里的「演示模式」，所有 AI 功能用本地规则生成示例结果，可以先把流程走一遍（结果带「（演示）」字样，不要当真）。
3. 「简历库」打开一份简历开始用。

## 功能

### 1. 简历库 / 编辑器
- 列表（缩略图）、新建（从空白模板或从现有简历复制）、复制、改名、删除、导出 PDF。
- **简历模板**：7 套风格可一键切换（同一份 `body.html`，只换主题 CSS，编辑 / AI 改写 / JD 定制 / 英文版 / 一页纸检查 / PDF 全部照常工作）。简历库和编辑器里都有带缩略图的模板选择器，并可快速调节主题色、字号、行距、页边距。选择保存在该简历的 `meta.json`。
  - **经典蓝**（默认）：保留原有蓝色经典版式；
  - **简约黑白**：校招通用的黑白极简；
  - **商务深蓝**：深色页眉 + 左侧色轨的双栏观感；
  - **互联网科技**：青紫渐变色条与左侧刻度标题；
  - **学术研究**：居中衬线、米色纸面；
  - **国际商务**：大号姓名、小型大写标题、拉丁字体优先；
  - **彩色标题条**：模块标题带色块底栏。
  经典蓝的基础版式在 `template/resume.css`，其他模板在 `template/themes.css` 中按主题覆盖。
- A4 原样预览（与导出 PDF 一致），缩放、自动分页（标题不落单在页底）。
- 「编辑」模式下直接点字修改，粘贴自动转纯文本；回车：在 bullet 里新起一条，在标题 / 描述行里只插入换行（不会把文字拆成竖排的几列）；段首退格 / 段尾 Delete 只合并同一列表的 bullet，不会把 bullet 并进描述行或把两段经历并在一起；`Ctrl+S` 保存，`Ctrl+Z` 撤销上一次写回或结构操作。每次保存前自动备份到 `resumes/<名称>/.history/`（保留 30 份），可在「历史版本」里预览 / 恢复。结构操作后也会自动写入历史。

- **重命名**：简历库卡片标题和编辑器顶部标题均可双击，或点旁边的「T」铅笔按钮，进入内联编辑；Enter 保存，Esc 取消。名称不能为空、不能以 `.` 开头、不能包含 `\ / : * ? " < > |`、最长 80 字，且不能与已有简历重名。重命名后，投递记录、JD 的基础/定制版引用、模拟面试会话与错题本中的简历名会同步更新。简历**正文里的姓名**（`.user-name`）在「编辑」模式下可以直接点击修改，这与「简历文件名」是两回事。
- **头像与校徽**：只保留页眉右上角那一个校徽（`.user-school`），教育经历条目不再单独放校徽（升级时会自动清掉已有的条目校徽）。没有头像/校徽时，编辑态会在相应位置显示虚线占位「+ 添加头像 / + 添加校徽」（仅编辑态，不进 PDF 和预览导出）。已有图片时，鼠标悬停会出现「更换 / 编辑 / 删除」工具条。这些按钮画在预览 iframe 外面的 overlay 上，不会写进 `body.html`，也不会进入发给 AI 的文本。也可用工具栏的图片按钮。支持文件选择、拖拽和 Ctrl+V 粘贴。编辑弹窗可裁剪（头像可选证件照 3:4 或 1:1）、缩放、选择圆形 / 圆角 / 方形。图片压缩后存到 `resumes/<名称>/assets/`。复制简历、JD 定制版、英文版会一并复制图片。商务深蓝模板也会在深蓝页眉右侧显示校徽（约 18mm，不溢出）。
- **结构编辑（增删改查）**：编辑器左侧「简历结构」按条目做成填报卡片：
  - **模块**（教育 / 实习 / 项目 / 研究 / 技能 / 奖项 / 证书 / 自我评价 / 组织 / 自定义等）：新增、删除、重命名标题、隐藏/显示、拖拽排序。新模块会套用模板里已有的模块 DOM 结构与类名，7 套主题样式都能用。
  - **条目**（一段经历）：新增（克隆该模块已有条目的编辑框结构，只换成【待补充】占位，标题在左、日期在右，与原有条目对齐）、复制、删除、上下移动。也可点「从素材库插入」，把一条经历素材变成新条目。
  - **填报卡片**：每条经历（教育 / 实习 / 工作 / 项目 / 研究 / 组织）在左侧是一张卡片，集中填写名称、开始时间、结束时间（写入预览里原来的三段日期）、角色、地点和描述/要点，不再是标题行外再散落一串小输入框。荣誉 / 证书是「名称 + 时间」一张卡片；技能 / 自我评价 / 个人总结整模块一张卡片、一个文本框。点预览中的条目会选中并滚到对应卡片；新增条目会打开同一形状的空卡片，结构与已有条目对齐。
  - 「编辑」模式下**点击**模块或条目即选中它：蓝色实线框住当前条目，旁边出现上移 / 下移 / 复制 / 新增 / 删除的小工具栏（overlay，不污染正文）。同一时间只有一个选中项；点另一条会换过去，点空白处、简历外面或按 `Esc` 取消。工具栏竖排停靠在纸张右侧留白里，与选中框顶部对齐，不压任何内容；放大后右侧留白滚出视野时，改放在选中框下方。悬停只显示淡淡的虚线提示。
  - 所有结构操作支持 `Ctrl+Z` 撤销，并会进入历史版本。
- 「ATS 纯文本」一键复制，用于网申表单粘贴。
- 工具栏「版本对比」可与另一份简历或历史版本并排、按模块对齐并逐字高亮差异（简历库也可进入 `#/compare`）。
- 「一页纸检查」会算出是否超出一页及大约超出多少行；一键让 Agent 给出各条删减建议和对比，由你逐条采纳，目标刚好一页。
- 「翻译成英文版」会**复制**当前简历为 `<名称>-EN`（不改中文原稿），保持 DOM 结构和 class 不变，把模块标题、日期（`至今` → `Present`，`2024年3月` → `Mar 2024`）、条目改成动词开头的专业英文。英文通常更长，译完后建议再做一次一页纸检查，并可切到「国际商务」模板。
- 导出 PDF 前会提醒还有几处【待补充】没填。

### 2. 简历 Agent（编辑器右侧）
- **诊断**：本地即时体检（页数、【待补充】、强表述、缺量化、超长句）+ AI 全面诊断（总分、分项评分、HR 10 秒印象、问题清单、高风险表述、需要你回答的问题）。诊断里的 P1、W1 等短编号会渲染成可点击的定位标签，点一下就跳到对应条目（不会把内部 DOM id 展示给模型或你）。每个问题也可「定位」或「AI 按建议改写」；也可「按全部建议改写」。
- **改写**：按条目或整个模块（大纲里的魔杖按钮），风格可选：精炼润色 / 技术强化 / 量化成果 / 精简压缩 / 情境重构 / JD 定向 / 自定义。「参考素材库」可选 **自动匹配**（按素材来源条目、标题、组织、技术栈对上所选条目）/ **手动选择** / **不使用**；选中的素材作为第二事实来源发给模型，只能用在对应的那段经历上。结果卡片会显示「引用素材」，并做「成稿检查」：单条超 90 字、超过 5 条、描述超过 2 句、新增「xx：」小标题、出现原文和素材里都没有的数字、套话。结果以「原文 vs 新文」逐字对比展示，可采纳 / 微调后采纳 / 左右视图 / 放弃 / 全部采纳。**采纳只写回正文文字**，标题、公司、时间、样式不动；采纳后可「撤销」。
- **追问**：面试官视角的分观察面追问（口径与边界 → 方案与权衡 → 岗位对齐 → 临场情境），每题附「回答应覆盖的事实」，外加 1 分钟自我介绍草稿。
- **对话**：针对这份简历随便问，可结合某条 JD。发给模型前，电话和邮箱会打码。

### 3. JD 适配（5 步）
1. 粘贴 JD（公司、岗位、链接、原文），选择基础简历；也可粘贴岗位链接后点「抓取」，或把整页文字 / HTML 粘贴后点「从粘贴抽取」，由规则 + LLM 抽出公司 / 岗位 / JD 正文并自动填入。
2. 解析：岗位主线、硬性条件（分权重）、核心职责、技能、加分项、隐性考察点、ATS 关键词（右侧预览里高亮已命中的词）；
3. 匹配诊断：6 维评分 + 「岗位条件对照表」（材料充分 / 表述偏弱 / 尚未体现 / 待向你确认 / 不宜牵强写入），给出投递建议（强匹配 / 可投 / 有风险 / 不建议）、缺口、不宜牵强写入的项；
4. 一键生成定制版：自动复制出 `我的简历-字节跳动-大模型应用开发实习` 这样命名的新简历，调整模块 / 条目顺序、改写相关条目，没有证据的要求**不会写进简历**而是列在「缺口」里；可勾选素材库经历作为证据来源（仍然不编造）；若 JD 是英文或勾选「生成英文定制版」，会在定制后再译为英文（名称带 `-EN`）；每处修改可单独恢复原文；同时可创建投递记录并关联；附 Boss 直聘开场白；
5. 面试追问：基于定制版简历和 JD 生成。
- **删除 JD**：左侧历史列表支持单条删除（悬停垃圾桶）和勾选后批量删除。删除前会二次确认，并可勾选「一并删除由它生成的定制版简历」（**默认不勾选**）。关联的投递记录只会解除 JD 关联，不会被删除。删除成功后右上角 toast 提供「撤销」。


### 4. 投递管理
- 日历（月视图，笔试 / 面试 / 截止日都显示在日历上，点日期快速新增）、看板（拖动卡片改状态）、列表（搜索、按状态筛选）、统计（漏斗、状态分布、近 12 周投递、渠道）。
- 每条记录：公司、岗位、状态、投递日期、渠道、城市、薪资、链接、截止日、关联 JD、使用的简历版本、内推人、备注、重点关注、日程列表、状态变化历史。
- 状态可在「设置 → 投递状态」里自定义（名称、颜色、所属阶段、顺序）。
- **投递提醒**（工作台首页）：未来两周即将到来的笔试 / 面试，以及投递超过 N 天（设置里可改，默认 7 天）仍停在「已投递」、没有回音的记录。可开启浏览器通知（Notification API，需授予权限，并保持工作台标签页打开）。支持导出 `.ics`：全部日程、某一条投递、或单个事件（可导入系统日历）。
- **投递复盘**（统计页下部）：按岗位类型 / 渠道 / 简历版本 / 公司类型看回复率、进面率、平均回复天数，以及回复→进面→Offer 漏斗。可让 Agent 基于数据给投递策略建议；样本量小于 8 时会明确提示结论不可靠。

### 5. 经历素材库（侧栏「素材库」）
- 按「情境—任务—行动—结果」结构化保存项目 / 实习 / 竞赛 / 科研 / 组织等完整经历：背景、任务、行动、结果、数据、技术栈、标签、证据链接。
- 可从现有简历一键导入，再用 Agent 引导式追问补全缺口。
- **从本机项目生成**：填项目目录绝对路径（Windows / macOS / Linux 均可；不允许磁盘根目录和整个用户主目录），可选填「我的角色 / 补充说明」（当作你亲口给出的事实）和 Git 作者名 / 邮箱（留空自动取该仓库的 `git config user.name / user.email`，用于只统计你本人的提交）。
  1. **扫描**：只读。Git 仓库用 `git ls-files` 按 `.gitignore` 过滤，否则遍历目录；固定跳过 `node_modules`、`.git`、`dist`、`build`、`out`、`target`、`.venv`、`__pycache__`、`.next`、`.idea`、`.vscode`、`vendor`、`coverage` 等目录，图片 / 字体 / 压缩包 / 可执行文件只计数，锁文件只看文件名判断包管理器。收集：目录树（3 层）、README、依赖清单（package.json、pyproject.toml、requirements.txt、go.mod、Cargo.toml、pom.xml、build.gradle、*.csproj、composer.json、Dockerfile、docker-compose、Unity ProjectVersion 等）、按语言的文件数和非空行数、接口路由粗略计数、顶层模块、Git 统计（总提交、参与人数、首末日期、本人提交与改动最多的目录、最近 50 条提交说明）、抽样几份入口 / 改动最多 / 体量最大的源码。上限：最多遍历 5000 个文件，总共 6 万字符，单文件 6000 字符，整体 25 秒。预览里列出每个要发送的文件和字符数，可展开查看全文。
  2. **密钥**：`.env*`、`*.pem`、`*.key`、`*.p12`、`id_rsa*`、`credentials*`、文件名含 secret / password 的文件、`.npmrc`、`.netrc` 等永不读取，也不出现在目录树里；所有发送内容再过一遍脱敏（`sk-…`、`ghp_…`、`AKIA…`、JWT、私钥块、连接串密码、`key= / token= / password=` 后面的值、长十六进制串）。
  3. **生成素材**：Agent 按素材库字段起草（结构化输出），数字只用程序统计出来的，并逐条写明依据文件；代码证明不了的（用户规模、性能提升、上线情况、个人分工等）写成【待补充】并列入待确认问题，保存时写进「结果」。可直接「保存到素材库」，或「先在编辑页修改」再保存；之后用右侧深挖逐条补齐。扫描结果只在内存里保留 30 分钟。
- JD 适配、诊断、改写会把素材库当作证据来源，**仍然不编造**；生成定制版时可勾选要使用的经历。

### 6. 模拟面试（侧栏「模拟面试」）
- 选择简历 + JD（或一条投递记录），选面试类型（技术一面 / 项目深挖 / HR 面）和轮数，Agent 扮演面试官多轮一问一答。
- 结束后给出复盘打分、每题点评和参考答法；薄弱题可进「错题本」重练。会话历史保存在本地 `data/interviews.json`。
- 若浏览器支持 Web Speech API，输入框旁会出现麦克风；不支持则自动隐藏。

### 7. 大模型设置
- 任何 OpenAI 兼容的 `/chat/completions` 接口都可用，流式输出经本地后端代理（浏览器里拿不到 Key）。
- Key 保存在 `data/config.json`（已加入 `.gitignore`），也可以用环境变量（优先级更高）：

```powershell
$env:LLM_API_KEY  = "sk-..."                      # 也认 OPENAI_API_KEY / DEEPSEEK_API_KEY
$env:LLM_BASE_URL = "https://api.deepseek.com/v1"
$env:LLM_MODEL    = "deepseek-chat"
$env:LLM_MOCK     = "1"                            # 强制演示模式
npm start
```

- 模型名可以自由填写（预设里的只是默认值，厂商改名了直接改即可）。推理模型（如 deepseek-reasoner）的思考过程会显示在进度框里。
- **结构化输出（v4.5）**：诊断、改写、JD 解析/匹配/定制、面试追问、一页压缩、翻译、模拟面试、素材深挖/成稿、投递策略等 JSON 任务，会优先向模型发送 JSON Schema（`response_format.json_schema`，strict）。若该模型接口返回 400/422 并提示不支持，会自动改用 JSON 模式（`json_object`），再不行就只用提示词约束，并在内存里记住该「Base URL + 模型」可用的方式，避免每次都先撞一次。设置里可改为强制 Schema / JSON 模式 / 关闭。无论哪种方式，解析失败仍会自动修复并重试一次。
- 未配置时，所有 AI 按钮都会提示「去设置」或「打开演示模式」。
- **获取模型列表**：填好 Base URL 和 Key 后，点「获取模型列表」。后端会代理调用 OpenAI 兼容的 `GET /models`（Key 不会进浏览器），结果出现在可搜索的下拉框里，仍允许手动输入。Ollama 会再尝试 `/api/tags`。若厂商不提供列表接口或请求失败，会回退到该预设的推荐模型并给出提示。可在「按任务指定模型」里为诊断 / 改写 / 面试分别填写模型名，留空则使用默认模型。


## Agent 的规则（防编造）

所有提示词在 `lib/agent/prompts.mjs`，核心规则：
- 先把问题说清楚，再改措辞；**只改说法，不改事实**；不编造公司、项目、工具、指标、上线状态；原文数字 / 时间 / 名称原样保留。
- 缺数据就写【待补充：要补什么】（简历里黄色高亮，导出前提醒），绝不虚构数字。
- 贡献语气只收不加重，内部阶梯为：配合 < 参与 < 承担 < 推进 < 牵头（原文若写「支持/协助、负责、推动、主导」，分别按配合、承担、推进、牵头理解）；「上线 / 企业级 / 显著提升」等强表述没有依据就改成更稳妥的说法。
- 关键词必须落在真实经历上；只出现在技能列表里最多算「仅有提及」。岗位写了但简历没有依据的列为缺口，不宜牵强写入。素材库只提供你已保存的事实，不会被用来编造新经历。
- 写法：动作 + 对象 + 难点 + 可核验的结果，重点和结果放在句子前半段，每条加粗 1-3 处，避开没有对应动作的套话。
- **简历成稿规范**（改写 / JD 定制 / 素材写成条目 / 一页压缩共用，`WRITING_SPEC`）：每条 bullet 约 40-80 字、硬上限 90 字；每个项目 2-5 条；项目描述 1-2 句、不超过 70 字；开头就是重点；原文没有「xx：」小标题就不加；不写「我」和套话；不新增原文和素材里没有的数字，缺数据写【待补充】。前端 `public/js/bullet-lint.js` 按同一组数值复查模型输出。
- 模型输出 HTML 只允许 p / ul / ol / li / strong / em / br，写回前再做一次白名单清洗。

对照与重写细节见 [docs/originality-report.md](docs/originality-report.md)。

## 数据目录、示例数据与清空

程序目录只放程序（`template/ public/ assets/ starter/ examples/`），用户数据单独放在数据目录，按下面的顺序确定：

1. 环境变量 `RESUME_HOME`（指定任意目录，比如同步盘）；
2. 程序目录里已有 `resumes/`（至少一份简历）或 `data/config.json`：沿用程序目录（4.7 及以前的旧位置，老用户不用迁移）；
3. 否则用系统用户目录：Windows `%APPDATA%\jd-resume`，macOS `~/Library/Application Support/jd-resume`，Linux `$XDG_DATA_HOME/jd-resume`（默认 `~/.local/share/jd-resume`）。

启动时终端会打印当前数据目录，设置页「本地环境」里也能看到。**更新**：用新版本整个替换程序文件夹（或 `git pull`）即可，数据目录不受影响。

**首次启动**：数据目录里没有初始化标记 `data/.initialized`、也没有任何简历时，复制一份入门模板「我的简历」（`starter/`，各模块都是占位文字）并写入标记；素材库、JD、投递、面试为空。之后删掉「我的简历」也不会再出现。新建简历时可选「从入门模板创建」（始终从程序目录的 `starter/` 读取）或「复制现有简历」。

**导入示例数据**（设置 → 数据管理）：把 `examples/` 里一位虚构候选人的两份简历（`张明`、`张明-字节跳动-大模型应用开发实习`）和配套的 JD、经历素材、投递（含 3 条日程）、模拟面试导入数据目录。同名简历跳过，数据按 id 合并，不覆盖已有内容。

**删除所有用户数据**（设置 → 数据管理）：两步确认（先确认要删除的内容，再输入「删除」），删除数据目录下的 `resumes/`（简历、历史版本）、`data/`（JD、素材、投递、面试、素材库、设置与 API Key）、`out/`（导出文件），然后恢复到第一次启动的状态。只删除这三个子目录，不会动程序目录里的模板、入门模板和示例数据。

## 命令行（原有功能保留）

```powershell
npm start                                 # 网页版工作台
node cli.mjs list                         # 列出所有简历
```

## 导 PDF

用本机 Chrome / Edge 无头打印，不装 puppeteer。默认通过 DevTools 协议打印（会等字体加载完成），失败自动退回 `--print-to-pdf`。

```powershell
$env:CHROME_PATH = "C:\Program Files\Google\Chrome\Application\chrome.exe"   # 找不到浏览器时
$env:PDF_ENGINE  = "cli"     # 强制用旧的 --print-to-pdf；"cdp" 只用协议方式
```

页边距由 `template/print.css` 的 `@page { size: A4; margin: 0 }` 控制。多页简历靠 `.main ~ .main { break-before: page }` 断页；如果多出空白页，把 `template/resume.css` 里 `.main` 的 `height: 297mm` 改成 `296.5mm`。

## 字体

项目不附带任何字体文件，只引用系统已安装的字体：中文依次尝试 PingFang SC、Microsoft YaHei、Noto Sans CJK SC、思源黑体（Source Han Sans SC）、Hiragino Sans GB，最后回退到系统无衬线字体。导 PDF 时由本机 Chrome 渲染，使用同样的系统字体；Linux 上建议安装 `fonts-noto-cjk`。

## 已知限制

- 分页在浏览器端按行位置估算；条目特别长时可能需要手动调整内容。`contenteditable` 编辑时大段删除 / 跨条目选中可能破坏结构，出问题用「历史版本」恢复。
- 演示模式只是规则模拟，质量不能代表真实模型；真实效果取决于所选模型。
- 数据只存在本地文件里，没有账号和云同步（数据目录见上文；可用环境变量 `RESUME_HOME` 放到同步盘目录）。
- 服务默认只监听 127.0.0.1，不要暴露到公网。抓取岗位链接时会拦截内网 / 元数据地址；本机 `127.0.0.1` / `localhost` 仅用于本地测试页。
- 版式是固定 A4，不做手机适配。英文通常比中文更占行，译完请用「一页纸检查」，并可切到「国际商务」模板。
- **JD 抓取限制**：很多招聘站需要登录或有反爬，自动抓取经常只能拿到登录墙、验证码页或职位已下线的壳页面。已知几乎抓不全的包括 **Boss 直聘（zhipin.com）**、**牛客部分职位**、**拉勾 / 猎聘 / 智联 / 前程无忧**（验证码或登录墙）、**LinkedIn**（几乎一定要登录）、**Indeed**（反爬）。企业官网和没有登录墙的静态岗位页成功率更高。失败时请把岗位页全文或「查看源代码」后的 HTML 粘贴到 JD 原文，再点「从粘贴抽取」。不要把账号密码交给本工具去登录招聘站。
- 浏览器通知需要授予权限，并且工作台标签页保持打开；关闭页面后不会在后台推送。Web Speech 语音输入取决于浏览器，不支持时按钮会隐藏。
